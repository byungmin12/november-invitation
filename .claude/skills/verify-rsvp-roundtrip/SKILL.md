# verify-rsvp-roundtrip

## 성질과 해악

**성질.** 손님이 초대장에서 적은 답변 d(참석 여부, 못 먹는 음식, 먹고 싶은 음식, 메모)를 초대장이 `[초대장 답변]` 텍스트로 만들고(`asText`), 호스트가 그 텍스트를 `admin.html`에 붙여넣어 다시 읽으면(`parseManual`) 손님 한 명의 답변 하나로, 네 값이 그대로 돌아와야 한다.

**해악.** 이 왕복에서 값이 잘리거나 비면 호스트는 손님이 못 먹는 음식이나 메모를 모른 채 장을 본다. 복사 모드는 `config.js`의 `ENDPOINT`가 비었거나 전송이 실패했을 때 쓰는 대체 경로라, 테스트가 거의 닿지 않는다.

## 적용 범위 (coverage record)

| 파일 | 함수·값 | 역할 |
|---|---|---|
| `assets/invite.js` | `asText(d)` | 답변을 다섯 줄 텍스트로 만든다. 빈 값은 `없음`, 미참석은 `미응답`으로 쓴다. |
| `assets/invite.js` | `collect()` | 입력값을 `trim()`해서 d 를 만든다. 검사의 입력 영역(다듬어진 문자열)이 여기서 온다. |
| `assets/admin.js` | `parseManual(text)` | `[초대장 답변]`으로 쪼개고 줄 단위 정규식으로 다섯 키를 읽는다. `없음`·`미응답`은 빈 값으로 되돌린다. |
| `config.js` | `GUESTS` | 이름 → guestId 대응. 이름이 목록에 없으면 guestId 에 이름이 들어간다. |

**동기화 커밋: `97765bb`.** 이 커밋에서 위 네 항목이 검사 설명과 일치함을 확인했다. 이후 커밋에서 이 파일들이 바뀌었으면(`git log 97765bb..HEAD -- assets/invite.js assets/admin.js config.js`) 검사가 여전히 코드를 설명하는지 읽어 보고, 확인한 뒤에만 이 커밋을 앞으로 옮긴다.

## 도구와 선택 이유

자바스크립트 코드 위에서 돌릴 검증기(모델 체커·증명기)가 이 저장소 환경에 없다. 그래서 모델을 손으로 만들지 않고 **실제 함수 소스를 이름으로 잘라 와 실행**하고, 유한한 입력 공간을 **전수 열거**한 뒤 **시드 고정 난수**로 넓힌다. 의존성은 없고 Node 22+ 만 있으면 된다. 결과는 재현 가능하다(기본 seed 20261121).

- 전수: 손님 5명 × 참석 2 × 필드 하나씩 토큰 10종(`a` `b` 공백 `:` `없음` `미응답` `[초대장 답변]` `메모` `이름` `참석`, 메모는 줄바꿈 포함 11종)의 길이 0~3 토큰열 전부. 약 2만 8천 경우.
- 난수: 세 필드를 동시에, 한글·구분 기호·이모지·줄바꿈을 섞은 길이 0~11 토큰열. 기본 2만 경우.
- 한계: 토큰열 길이 3 과 난수 2만 경우까지의 **유계 검사**다. 그 바깥(더 긴 조합)에서만 깨지는 반례는 놓칠 수 있다. 성질은 "trim 된 문자열"에 대한 것이며 `collect()`가 trim 을 보장한다는 가정에 기댄다. 운영 전송 경로(구글 시트)는 범위 밖이다.

## 실행

```
node .claude/skills/verify-rsvp-roundtrip/check.mjs             # 0.2초
node .claude/skills/verify-rsvp-roundtrip/check.mjs --strict    # 알려진 발견도 실패로
node .claude/skills/verify-rsvp-roundtrip/check.mjs --seed 7 --random 100000
```

종료 코드 0: 실패가 없거나 전부 아래 "알려진 발견"에 속한다. 종료 코드 1: 알려진 분류에 없는 **새 반례**가 있다(또는 `--strict`). 출력은 분류별로 가장 짧은 반례를 코드의 말로 보여준다. 입력 d, 그로 만든 텍스트, 그리고 어떤 필드가 무엇으로 바뀌었는지.

## 알려진 발견 (현재 코드가 성질을 깨는 경우)

성질을 약하게 만들지 않고 그대로 두었다. 고치기 전까지는 검사가 매번 이들을 보고한다. 고쳐지면 그 분류가 0건이 되고, 그때 아래 항목과 `check.mjs`의 `classify`에서 해당 분류를 지운다.

1. **`multiline-note` (해롭다).** 메모는 `<textarea>`라 여러 줄을 받는데, `parseManual`의 정규식 `^\s*메모:\s*(.*)$`는 첫 줄만 읽는다. 손님이 "늦을 것 같아요 / 와인 들고 갈게요"처럼 두 줄을 적으면 둘째 줄부터 사라진다. 반례: note `"a\nb"` → `"a"`. 고치려면 `asText`가 줄바꿈을 이스케이프하거나 `parseManual`이 다음 키 앞까지를 값으로 읽어야 한다.
2. **`none-literal` (무해한 정규화).** 손님이 직접 `없음`이나 `미응답`을 적으면 빈 값으로 돌아온다. 뜻이 같으므로 호스트에게 해가 없다. 성질상 반례라 기록만 한다.
3. **`marker-in-field` (실제로는 거의 안 일어남).** 값 안에 `[초대장 답변]`이 들어 있으면 블록이 쪼개져 그 값과 뒤 필드가 빈다. 손님이 그 문자열을 적을 이유는 없지만, 성질상 반례다.

## 이 검사가 깨지는 것을 본 기록

`assets/admin.js`에서 `get("먹고 싶은 음식")`을 `get("먹고싶은 음식")`으로 바꾸면 wantEat 이 항상 빈 값이 되어 `new` 분류로 종료 코드 1. `assets/invite.js`에서 `join("\n")`을 `join(" ")`으로 바꾸면 이름·참석까지 깨져 `new` 분류로 종료 코드 1. 둘 다 되돌리면 알려진 발견만 남는다. 한 번도 실패를 본 적 없는 검사는 아무것도 증명하지 않으므로, 검사를 고쳤다면 이 두 변경으로 다시 깨뜨려 본다.

## 다음 에이전트가 할 일

1. 변경이 위 표의 파일·함수를 건드리는가? `git diff --name-only`에 `assets/invite.js`, `assets/admin.js`, `config.js`가 있으면 그렇다. 아니면 이 검사는 무관하다.
2. 건드렸다면 `node .claude/skills/verify-rsvp-roundtrip/check.mjs`를 돌린다.
3. 종료 코드 1 이면 출력의 `[새 반례]`를 읽는다. 반례의 텍스트를 보고 그 변환이 사용자가 보기에 틀린 것이면 **코드 버그**다. 변경이 의도적으로 텍스트 형식을 바꾼 것이면 **검사 갱신**이다. `asText`와 `parseManual`이 서로 맞게 바뀌었는지 먼저 보고, 맞다면 `check.mjs`의 토큰 목록에 새 형식의 구분 문자를 추가하고 적용 범위 표와 동기화 커밋을 갱신한다.
4. 함수 이름이 바뀌어 "function … 가 없다"로 멈추면 `check.mjs`의 `extractFunction` 호출의 이름을 바꾸고 표를 고친다. 함수가 분리되거나 합쳐졌으면 검사도 그 경계를 따라간다.
5. 알려진 발견 중 하나를 고쳤다면 그 분류가 0건으로 떨어지는지 보고, 위 목록과 `classify`에서 지운다. 성질 자체는 바꾸지 않는다.

변경 뒤 검사를 다시 맞추지 않은 채 시간이 지났다면 `/pstack:maintain-formal-verification-skill`로 되돌린다.
